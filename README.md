# MySmartNews

カテゴリを選ぶだけで、自分好みに並ぶニュースリーダー。
データベースもログインも広告もなし、完全無料で運用できます。

- **27カテゴリから選ぶだけ** — 総合・国際・経済・IT・暮らし・グルメ・旅行・
  エンタメ・スポーツ・ゲームなど、はじめから一通り揃っています。初回は
  よく読まれる7カテゴリが選ばれた状態で開くので、そのまま読み始められます。
- **設定は端末の中だけ** — カテゴリ・キーワード・ミュート・学習した話題・
  既読の記録はすべて localStorage に保存され、サーバーには一切送られません。
  アカウントは存在しません。
- **TOPは3種類を混ぜた1本のリスト** — 「複数の媒体が同時に報じている大きなニュース」
  「あなたの興味に沿った記事」「購読ソースの新着」を、カテゴリで区切らず織り交ぜます。
  下まで読むと自動で継ぎ足され、一度見た記事は次から下がります。
- **重要度とは、何媒体が報じたか** — はてなブックマーク数は「話題度」であって
  重要度ではないので、大きなニュースの判定には使いません。同じサイトが一覧を
  独占しないようにも調整済み。
- **アプリライクUI** — スワイプで切り替わるタブ。ダークモード対応。
  iPhoneのホーム画面に追加（PWA）できます。
- **サーバーレス** — GitHub Actions が記事を集め、静的ファイルとして配信します。

設計の背景と判断の理由は [docs/DESIGN.md](docs/DESIGN.md) にまとめてあります。

## TOPの仕様

### 何を目指しているか

**「誰もが知るべきニュース」を取りこぼさず、そのうえで飽きずに読み続けられること。**
この2つは要求が逆向きなので、1本のスコアでは両立しない。そこで性格の違う3つの
選び方を並行して走らせ、**分類して見出しで区切るのではなく、決まった比率で
織り交ぜた1本のリスト**にしている。

### 3つのレーン

| レーン | 何を選ぶか | 決め手 | カードの表示 |
|---|---|---|---|
| 主要 | 誰もが知るべきニュース | **何媒体が報じたか**（3媒体以上）。鮮度は半減期20時間 | `主要` バッジ |
| あなた向け | 興味に沿った記事 | 興味キーワード＋自動で覚えた話題＋よく読むサイト | マッチした語をバッジ表示 |
| 新着 | 購読ソースの新しい記事 | 鮮度（半減期8時間）＋よく読むサイト＋はてブ | バッジなし |

供給比率は `主要 → あなた向け → 新着 → あなた向け → 新着` の繰り返し
（`app.js` の `MIX_PATTERN`）。先頭が主要なので、大きなニュースがあれば開いた
瞬間に見える。尽きたレーンの順番は残りが埋めるので、興味キーワードを1つも
設定していない人のTOPは自然と新着中心になる。

### 重要度をどう決めているか

**はてなブックマーク数は使わない。** ブックマーク数が測っているのは
「ネットで語りたくなる度」であって「重要度」ではないため。それだけで並べると、
他社が誰も追随していない個人の意見記事が構造的に上に来てしまう。

代わりに使うのが **reach（同じ話題を何媒体が報じたか）**。大きなニュースほど
多くの媒体が同時に報じる、という当たり前の性質をそのまま指標にしたもので、
個人ブログには原理的に効かない（誰も追随しないので reach は 1 のまま）。
カードの `N媒体` バッジがこの数字。

はてブは捨てたわけではなく、「新着」レーンの弱い後押しと `急上昇` バッジに
降格した。はてなブックマークのランキングそのものは「話題」タブに残るので、
見たい人はそこで見られる。

さらにソースには **tier**（`wire` / `media` / `search` / `social`）を持たせ、
はてブのランキング経由（`social`）はTOPでの重みを下げている。

### パーソナライズ（すべて端末の中だけ）

| 仕組み | 何をするか | 消し方 |
|---|---|---|
| 興味キーワード | 手で登録した語をタイトルに含む記事を上げる（弱・中・強） | 設定 → 興味のあるキーワード |
| 自動で覚えた話題 | **開いた記事の見出しから語を拾って重みを育てる。** キーワードを1つも設定していなくてもおすすめが効く | 設定 → 自動で覚えた話題 |
| よく読むサイト | 開いた回数の多いサイトを上げる | 設定 → 設定の持ち出し |
| もう見た記事 | 一覧に出した記事を覚え、次はスコアを 1/4 にする | 設定 → 設定の持ち出し |

覚えた語は開くたびに少しずつ薄れる（`LEARN_DECAY`）ので、興味が変われば
放っておいても入れ替わる。形態素解析器は積まず、カタカナ語・英単語・漢字熟語を
拾う正規表現で近似している。

> 「自動で覚えた話題」が空のままなら、まず **設定 → バージョン** を見てください。
> 「いま動いているアプリ」と「配信されているアプリ」がずれていたら、ブラウザが
> 古いファイルを保持しています。再読み込みで新しくなります。

### 飽きずに読み続けるための工夫

- **無限スクロール** — 20件ずつ描き足す。数百枚のカードを一度にDOMへ載せない。
- **在庫が尽きたら視野を広げる** — 購読ぶんを出し切ったら、購読していない
  カテゴリを1つずつ読み込んで継ぎ足す。購読を勝手に増やすことはしない。
- **既読の抑制** — 一度出した記事は次から下がるので、再訪すると顔ぶれが変わる。
- **多様性の担保** — 同じサイトが1件増えるごと、同じ話題が1件増えるごとに
  スコアを割り引く（貪欲MMR）。更新頻度の高いサイトや1つの大事件が一覧を
  独占しない。

各定数は `app.js` 冒頭にまとまっている。なぜそう決めたかは
[docs/DESIGN.md](docs/DESIGN.md)。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `catalog/index.json` | カテゴリ（パック）の一覧。**カテゴリを増やすならここ** |
| `catalog/packs/<id>.json` | そのカテゴリのソースと推奨キーワード |
| `index.html` | 表示側の骨格。初回訪問者向けの説明とメタ情報もここ |
| `style.css` | 見た目 |
| `app.js` | 表示側。並べ替えと設定画面はすべてここ |
| `build.py` | 記事を収集して `dist/` を生成する（GitHub Actionsが毎時実行） |
| `functions/api/` | Cloudflare Pages Functions。ユーザーが自分で足したソースの取得に使う |
| `dist/` | 生成される配信物（gitignore） |
| `data/state.json` | ビルド間で引き継ぐ状態。7日以内に見た記事のメタ情報のみ（gitignore） |

`dist/robots.txt` と `dist/sitemap.xml`、`index.html` の canonical・OGP は
ビルド時に生成されます。配信先のURLは環境変数 `SITE_URL` で指定します
（既定は `https://mysmartnews.pages.dev`）。

記事データはリポジトリにコミットされません。生成物は毎時 Pages へ直接デプロイされます。

## カテゴリを増やす・直す

`catalog/` を編集して Pull Request を送ってください。次回の自動更新から反映されます。

### 1. カテゴリを足す

`catalog/index.json` の `packs` に1行足し、同じ `id` で `catalog/packs/<id>.json` を作ります。

```json
{
    "id": "camera",
    "name": "カメラ",
    "description": "写真とカメラ機材の話題。",
    "order": 12,
    "default": false
}
```

`order` は設定画面での並び順です。番号が飛んでいても構いませんが、重複はできません。
`default: true` にすると、初めて開いた人にあらかじめ選択された状態で出ます。
`description` は設定画面だけでなく、初回訪問者向けの説明と検索エンジンにも
そのまま出るので、**そのカテゴリで何が読めるかが1行で分かる文**にしてください。

### 2. ソースを書く

**公式RSSがあるサイト（推奨）**

```json
{"id": "example", "name": "サイト名", "type": "rss", "url": "https://example.com/rss"}
```

**キーワード検索（Googleニュース）**

```json
{"id": "q-camera", "name": "ミラーレス", "type": "query", "query": "ミラーレス OR 交換レンズ"}
```

登録していないサイトの記事も流れ込みます。`site:example.com` と書けば、RSSを持たない
サイトをスクレイピングなしでフィード化できます。ただしサムネイル画像とはてブ件数は
付きません（理由は [docs/DESIGN.md](docs/DESIGN.md)）。

**RSSがないサイト（HTMLスクレイピング）**

```json
{
    "id": "example-html",
    "name": "サイト名",
    "type": "html",
    "url": "https://example.com/news",
    "selector": "article h2 a",
    "include": "^https://example\\.com/atcl/",
    "exclude": "/(tag|category)/"
}
```

`selector` はできるだけ具体的に。それでもナビゲーションが混ざるときは `include`
（残すURLのパターン）と `exclude`（捨てるURLのパターン）で絞れます。除外はソース
あたりの取得上限（30件）を数える前に行われます。

※ スクレイピングでは公開日時が取れないため、**初回に発見した時刻**を代わりに使います
（タイトル末尾が `2026年8月21日` のような日付で終わっていれば、それを切り離して使います）。

### 3. ソースの性質（tier）

TOPの重み付けに使います。省略すると `query` は `search`、それ以外は `media` に
なるので、**通信社・公共放送とソーシャルブックマーク経由のときだけ**書けば十分です。

```json
{"id": "nhk", "tier": "wire", "name": "NHKニュース", "type": "rss", "url": "..."}
```

| tier | どんなソースか | TOPでの扱い |
|---|---|---|
| `wire` | 通信社・公共放送。速報の一次情報 | 少し重く見る |
| `media` | 商業メディア（既定） | 基準 |
| `search` | 検索フィード経由（`query` の既定） | やや軽く見る |
| `social` | はてブなどランキング経由 | 軽く見る。専用タブでは今まで通り |

はてなブックマークのランキングは「話題度」であって「重要度」ではないので、
TOPの主要ニュース枠には載せません（詳しくは [docs/DESIGN.md](docs/DESIGN.md)）。

### 4. 推奨キーワード

パックを購読した人の興味キーワードに、未登録のものだけ取り込まれます。
そのジャンルに詳しい人の勘所をプリセットとして配れる枠です。

```json
"suggested_interests": [
    {"word": "BIM", "weight": 1.2},
    {"word": "建設DX", "weight": 1.2}
]
```

書くときの決まりごとが2つあります。**取り込まれた語はそのパックの中だけでなく
TOP全体に効く**（購読者の興味キーワードそのものになる）ので、どちらも
「1カテゴリ足したせいで他が読めなくなる」を防ぐためのものです。

- **1パックあたり2〜5語、重みは 0.5〜1.2 に収める。** 2.0 のような重みは、
  そのカテゴリを1つ足しただけでTOPがその話題で埋まります。
- **短い語・どこにでも出る語を書かない。** 判定はタイトルの**部分一致**なので、
  `AI` は「メイン」「WAI」に、`本` はほぼ全部の記事に当たります。
  `生成AI` `保護猫` のように、それ自体で意味が決まる長さの語を選んでください。

## 自分で運用する

### Cloudflare Pages（推奨）

帯域無制限で、ユーザーが自分でソースを足す機能（Pages Functions）も使えます。

1. Cloudflare で Pages プロジェクトを作る（Direct Upload を選択）
2. GitHub のリポジトリ設定 → Secrets に `CLOUDFLARE_API_TOKEN` と
   `CLOUDFLARE_ACCOUNT_ID` を登録
3. プロジェクト名が `mysmartnews` 以外なら、Variables に
   `CLOUDFLARE_PROJECT_NAME` を登録
4. 独自ドメインなど `https://<プロジェクト名>.pages.dev` 以外で配信するなら、
   Variables に `SITE_URL` を登録（canonical・OGP・sitemap.xml に入ります）
5. Actions の «Update News» を手動実行

`wrangler pages deploy` による Direct Upload は Pages のビルド数上限
（無料枠 500回/月）を消費しないため、毎時デプロイでも無料枠に収まります。

### GitHub Pages

Cloudflare のシークレットを設定しなければ、自動的に GitHub Pages へデプロイされます。
リポジトリ設定 → Pages → Source を **GitHub Actions** に変更してください
（旧来のブランチ配信からの移行が必要です）。

この場合、ユーザーが自分でRSSやキーワードを足す機能だけは使えません
（ブラウザから外部フィードを直接読めないため）。設定画面ではその欄が隠れます。

## 開発

```bash
pip install -r requirements.txt

python build.py                     # dist/ を生成
python -m http.server 8000 -d dist  # http://localhost:8000 で確認

python tools/validate_config.py     # catalog/ の検証
python tools/build_smoke_test.py    # ネットワークをスタブしたビルドの回帰テスト
node tools/rank_smoke_test.js       # 並べ替え（ブラウザ側）の回帰テスト
```

カタログにソースを足したら、実際に取れるかを見てください（外部サイトへ
出ていくのでCIには入れていません）。

```bash
python tools/check_sources.py       # 全ソースを1件ずつ取得して結果を出す
python tools/check_sources.py it ai # パックを指定
```

RSSの移転やセレクタのずれは「0件」として静かに進むだけでビルドは通ってしまうので、
`空` と出たソースは直すか外してください。

実ブラウザでの確認（CIには入れていません）:

```bash
pip install playwright && playwright install chromium
python -m http.server 8765 -d dist &
python tools/e2e_test.py
```

`dist/` にはビルドが `index.html` / `app.js` / `manifest.webmanifest` / `_headers` を
コピーします。表示だけ直したいときも `python build.py` を通してください。
